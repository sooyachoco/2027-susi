# 2027 수시 서울권 데이터 구조 감사

> 감사일: 2026-09-04
> 범위: 서울 1차 43개교 / 경기·인천 제외 / 신학대학 제외

## 1. 이번 감사에서 확인한 핵심

현재 프로젝트는 대학별 데이터 파일이 상당히 많이 축적되어 있지만, **데이터 파일의 존재와 실제 서비스 Repository 편입 여부가 분리되어 있다.** 따라서 앞으로는 대학을 새로 만드는 작업보다 `파일 존재 → Repository 편입 → 실제 서비스 노출 → 데이터 품질`의 4단계 검증을 우선한다.

`lib/admission/hybridRepository.ts`는 현재 검증된 2027 데이터만 `isMock !== true` 조건으로 모으고 있으며, 대학/학과도 실제 검증 전형이 존재하는 경우에만 노출하도록 구성되어 있다.

## 2. 구조상 발견된 위험요소

### A. `lib/admission/verified/`에 별도 검증 파일이 다수 존재

현재 다음과 같은 대학별 파일이 별도 디렉터리에 존재한다.

- `ajou2027.ts`
- `deoksung2027.ts`, `dukseong2027.ts`, `duksung2027.ts`
- `dongduk2027.ts`
- `gwangwoon2027.ts`, `kwangwoon2027.ts`
- `hansung2027.ts`
- `kookmin2027.ts`
- `myongji2027.ts`
- `sammyung2027.ts`, `sangmyung2027.ts`
- `seokyeong2027.ts`
- `seoultech2027.ts`
- `seoulwomen2027.ts`
- 여러 `seoul_*_batch2027.ts`

이 파일들은 현재 `hybridRepository.ts`에서 직접 전부 사용되는 구조가 아니다. 일부는 이미 상위 디렉터리의 별도 모듈로 재작성되어 연결되어 있으므로 **무조건 추가 연결하면 중복 데이터가 생길 수 있다.**

### B. `verifiedNextSeoul2027.ts`는 검증 데이터로 오인할 위험이 있음

이 파일에는 홍익대·경희대·한국외대·숙명여대·성신여대 등의 학과 목록과 함께 학생부종합/교과/논술을 일괄 생성하는 구조가 존재한다.

특히 논술 수능최저 설명이 `공식 2027 수시 모집요강 확인`처럼 실제 모집단위별 기준을 담지 않은 일반 문구로 구성되어 있다. 따라서 **이 파일을 실제 추천 데이터에 연결하지 않는다.**

### C. 보류 대학은 계속 보류

다음 8개교는 기존 작업 원칙대로 이번 감사에서도 Repository에 신규 편입하지 않는다.

- 서울대학교
- 연세대학교
- 고려대학교
- 서강대학교
- 중앙대학교
- 경희대학교
- 한국외국어대학교
- 이화여자대학교

단, 저장소 안에 기존 verified 파일이 존재하는 것 자체는 허용한다. 실제 서비스 Repository에는 편입하지 않는 것이 기준이다.

## 3. 현재 Repository의 방향성

현재 `HybridAdmissionRepository`는 다음 안전장치를 가지고 있다.

1. `academicYear === 2027`만 사용
2. `isMock` 데이터 제외
3. 실제 전형이 존재하는 대학만 대학 목록에 노출
4. 실제 전형이 존재하는 학과만 학과 목록에 노출
5. 동일 ID는 마지막 데이터 기준으로 dedupe
6. 서울/경기/인천/충남 지역 범위 필터 적용

따라서 향후 작업은 **새로운 mock/임시 데이터 파일을 만드는 방향보다 기존 verified 데이터의 품질과 연결 상태를 개선하는 방향**으로 진행한다.

## 4. 다음 감사 우선순위

### P0 — 데이터 오염 방지

- `isMock: false`인데 실제 모집인원/전형방법이 없는 데이터 탐지
- 수능최저 설명이 일반 문구인 데이터 탐지
- `recruitmentCount`가 비어 있는 핵심 전형 탐지
- source URL/document가 없는 데이터 탐지
- 존재하지 않는 departmentId/universityId 참조 탐지

### P1 — 중복 정리

- 동일 대학의 상위 디렉터리 모듈과 `verified/` 모듈 비교
- 같은 대학의 여러 batch 파일에서 동일 admission ID가 반복되는지 확인
- 동일 대학명이 다른 universityId로 중복 등록된 경우 통합 후보 생성

### P2 — 서울 43개교 완전성

- 대학별 실제 서비스 노출 여부
- 학과 목록의 실질적인 누락 여부
- 전형 목록의 누락 여부
- 모집인원 공백 여부
- 전형방법/수능최저/면접/논술 정보 공백 여부

## 5. 작업 원칙 변경

이제부터는 다음 순서로 작업한다.

**전체 감사 → 위험/누락 목록 생성 → 3~5개 묶음 수정 → Repository 연결 → 빌드 확인 → 다음 감사**

대학별 파일을 무작정 추가하지 않는다.

## 6. 현재 결론

현재 프로젝트는 단순히 '대학 데이터가 부족한 상태'라기보다, **이미 만들어진 데이터가 여러 세대의 파일과 batch 구조로 분산되어 있어 전체 품질을 한 번 정리해야 하는 단계**다.

따라서 다음 작업은 신규 대학 추가보다 `hybridRepository.ts`를 기준으로 서울권 데이터의 실제 노출·누락·중복·위험 데이터를 찾아내는 전수 감사부터 진행한다.
